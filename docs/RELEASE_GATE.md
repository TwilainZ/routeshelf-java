# 阶段验收与统一交付

维护者要求先完成一阶段的功能完善，再一次进行必要的 Google 配置和手机验收。中间提交留在开发分支和草稿 PR，不反复提供安装包，不要求每次构建重新注册客户端。

## 固定身份

预览包名继续使用 `dev.gdirect.lite.preview`，证书以 `config/preview-signing.json` 为准，复用仓库外保留的私钥。普通功能变更不更换包名或密钥。缺失原密钥时停止打包，不能自动生成替代密钥。Google 客户端注册与 APK 签名是不同操作；同一包名/证书的更新不需要再次注册客户端。当前预览客户端尚未由维护者添加，留到统一验收阶段处理。

## 本阶段核心范围

- 自动直连覆盖公开下载、私人列表及下载；首次探测、缓存、失效换线、取消、网络切换和无可用线路的恢复。
- 文件夹、搜索、分页、元数据、公开确认页、单流及安全分块下载、完整性检查和系统 Downloads 保存。
- 临时读取错误有界退避；遵守 Retry-After；权限、证书、文件版本和本地存储错误不作为网络错误反复重试。私人中断后从头重新读取和校验，不跨会话拼接未验证内容。
- 会话失效、断开、取消、磁盘空间不足、应用重建、前台服务限制等失败路径应明确，不发布不完整文件。
- 界面应清楚区分登录、数据线路和下载状态，支持小屏、夜间主题、字体缩放及基础无障碍。

Google 文档导出、共享云端硬盘、快捷方式、上传、队列和任意自定义 SNI 仍是已知功能差距，不能宣称已经与桌面项目功能齐全相当。挂载等桌面特有能力需另行按 Android 平台设计。功能流程可参考原项目，代码继续独立实现。

## 交付门槛

1. 原型解析检查、真实 TLS/协议/会话测试、最终配置的 Gradle 编译和 Lint、GitHub Actions 通过；验证实际 APK 的包名、证书及提交，拒绝错包。
2. 用可控服务验证重试、断线、内容变化、限流及取消，避免只测试成功路径。证据注明哪些是 JVM/回环测试，哪些是 Android 设备结果。
3. 整理一份面向手机的验收清单，再统一交付；Google 配置只需补齐固定预览身份的一条 Android 客户端，不重新初始化现有项目。
4. 真机登录、私人下载和中国网络关闭代理后的直连必须由真实环境验证。尚未具备证据时保持未完成状态，不能以“编译成功”宣布软件已全部做好。

当前密钥只确认保留在云环境，CI 未配置相应 Secret，外部安全备份尚未完成；不能把当前保留状态说成长期备份已落实。维护者现有旧版继续保留。
