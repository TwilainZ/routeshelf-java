# 发布前检查

## 通用

1. 从干净的 Git 提交构建。发布说明应包含版本、构建提交、校验值、实际验证和待验证范围。
2. 按目标平台运行测试、编译和 Lint。网络改动要覆盖失败和凭据边界。分别记录回环测试、设备测试、真实账号和运营商网络结果。
3. 发布二进制时在同一下载位置提供对应源码的获取方式，保留许可和第三方声明。详见 [分发安装包](LICENSING.md#分发安装包)。
4. 凭据、签名私钥和未脱敏日志留在构建和测试环境之外的安全存储中，勿上传到 Git、工件或 Issue。

## Android

- 运行 `bash tools/check.sh`。使用仓库外的保留密钥运行 `bash tools/build-preview-apk.sh` 生成固定签名预览。
- 检查 `APK-IDENTITY.json`、SHA-256、版本码、提交、包名、[签名指纹](../config/preview-signing.json) 及证书资源。保留 `dev.gdirect.lite.preview` 和同一签名，既有用户才能正常升级。
- 缺少正确私钥时停止交付固定签名预览。调试 APK 和离线检查器各有用途。
- 依据 [设备验收](ACCEPTANCE.md) 检查覆盖安装、授权、文件操作、连接与传输。
