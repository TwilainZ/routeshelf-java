# Android IPv6 与 Java 网络核心

0.8.5 在原有 Java 连接引擎上增加双栈，不替换授权、文件浏览、预览、管理或传输实现。默认仅 Google、主动同意后的已知中转、系统网络三种模式保持，包名和固定预览签名保持。

## 行为参考与独立实现

本轮阅读了原项目最新版 [网络说明](https://github.com/mizorewww/gdirect/blob/e49215922528fe6f82c286eaade365927c0f1c61/docs/network.md)、[IPv6 更新说明](https://github.com/mizorewww/gdirect/blob/e49215922528fe6f82c286eaade365927c0f1c61/CHANGELOG.md)及扫描源码的 IPv6 入口/设计注释。参考的公开思路是全局 IPv6 可用时加入探测、Google 官方非 Cloud 范围过滤、与 IPv4 并行及证书/服务验证。没有复制或翻译其 Rust/C++ 实现、区域前端地址规律表、种子、补丁或测试。

本项目用自己的 Java 解析器、128 位区间运算、DNS/历史地址派生候选和受限工作队列实现。IPv6 文本依照公开 IPv6/RFC 4291 与 RFC 5952 规则处理。

## 连接路径

1. 当前 Android 网络同时具有全局 IPv6 地址和 IPv6 默认路由才启用自动 IPv6。只有链路本地/ULA 地址不算。IPv6 可用性、网络句柄或 VPN 状态变化都会使旧路线和连接池失效；不会声称固定 IP 绕过 VPN。
2. `IpLiteral` 只解析数字，拒绝主机名、端口、URI、zone ID 和含糊的 IPv4 写法；IPv6 统一小写并压缩最长零段，避免相同 IP 使用多个缓存身份。自动发现只接受公网单播，拒绝映射 IPv4、私有、文档、转译及保留空间。
3. 官方 goog.json 与 cloud.json 分别验证 IPv4/IPv6 前缀并独立相减。IPv6 用 BigInteger 处理 `/128` 等边界，不能截成 64 位；Google/Cloud 地址族不完整时不放行该目录。现有原始目录缓存可重新解析，不需要换 Google OAuth 客户端。
4. 系统 DnsResolver 加入可取消的 AAAA 查询。加密 DNS 在双栈时查询 A/AAAA，并可使用 Google 官方 Public DNS 的 IPv6 anycast 地址 `2001:4860:4860::8888`、`2001:4860:4860::8844`。它们只引导 dns.google，不当作 Drive 前端。每个回答检查问题名称、类型、CNAME 链与公网字面量；ECS 使用零长度网段，不携带账号、文件或令牌。无 IPv6 时仍只运行原有四个 IPv4/A 探测。
5. 候选按地址族交错。IPv4 保留最多 512 个扩展候选及原有 24 TCP/6 TLS 工作线程；IPv6 额外最多 128 个候选、4 TCP/2 TLS 线程。两族不会占用对方的探测线程，整体发现预算仍为 45 秒，成功后备用收集窗口不增加。IPv6 候选来源为自己取得的 DNS/历史结果，在其既有 `/64` 内对低位作有界邻域采样，每个地址仍过官方范围过滤；不遍历整个 `/64`，不导入区域地址表。
6. Socket 从已解析字节建立数字端点，不额外做 DNS。普通、无 SNI、固定 g.cn 身份保持相同 GTS-only 信任与逻辑 Host 分离；验证后才发送凭据。现有 GET 有界重试、写入不盲目重放、Range/ETag/校验及取消行为继续使用。日志和连接状态显示实际 IPv4/IPv6 地址族。

公开单文件的高级选项接受 IPv4 和 IPv6，可输入裸 IPv6 或 `[IPv6]`；不接受带端口或 zone 的写法。输入框支持十六进制字符和足够长度，其他操作层级不变。

0.8.6 的连接页显示当前网络是否具有全局 IPv6 地址、默认路由或尚未取得平台信息。日志 IPV6_STATUS 的 code：0 未知、1 离线、2 没有全局地址、3 缺少默认路由、4 满足双栈探测条件；这些状态不代表 Google IPv6 已连通。RANGE_IPV6_READY 记录非 Cloud 的 IPv6 区间数量，DNS_A_READY / DNS_AAAA_READY 记录过滤后的唯一候选数，不记录本机地址。系统网络模式仍由 Android/代理选族。日志保留旧会话，APP_START code 从本版起记录版本码，导出头只描述当前安装版本。

## 冷启动与验收范围

没有内置完整的官方 IPv6 范围快照。官方目录及有效缓存均不可用时仍使用原有六个 IPv4 引导候选；不把未经范围检查的 DNS IPv6 答案当作 Google 自有前端。系统网络模式由系统选择地址族。

回归覆盖字面量/规范化、IPv6 Cloud 排除和单地址边界、AAAA/CNAME/ECS、双向黑洞回退、网络变化、日志脱敏，以及 `::1` 上三种真实 TLS 身份、错证书拒绝和凭据边界。它们是本地协议与回环测试；真实手机、账号和中国各运营商 IPv6 连通性需要设备反馈。参考项目的 IPv6 更新说明同样没有给出中国网络实测结论。
