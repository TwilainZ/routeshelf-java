# 菜单与界面逻辑审查：0.8.4

本轮是对 Android Java、菜单、生命周期及现有手机反馈的源码审查和修正。没有当前连接的真机，未标记触控、返回手势、TalkBack 或新布局截图验收通过。0.8.3 的 Material 组件、蓝色日夜配色和 48dp 触摸目标保留。

## 当前层级

| 页面或入口 | 职责与下一步 |
| --- | --- |
| 首页 | 最近修改；标题是上下文，不再打开文件范围选择 |
| 文件 | 文件夹浏览；范围标题选择我的云盘、所有文件、星标、与我共享、回收站或共享云盘；底部仍只有首页和文件 |
| 浏览页主菜单 | 浏览组：刷新、排序；传输组：通过链接下载、传输详情；设置组：设置 |
| 顶部连接状态 / 设置 → 连接状态与检测 | 打开同一 ConnectionActivity；开始、取消和重试检测集中于该页 |
| 文件更多菜单 | 直接列出适用的打开/预览、下载/导出、详情、共享、复制链接、重命名、星标、移动、移至回收站；不再嵌套泛称“文件操作” |
| 回收站文件 | 详情、恢复、永久删除；点击文件夹也先看详情，不能绕过恢复直接进入 |
| 共享云盘入口 | 打开、详情；不把云盘 ID 当普通文件提供修改或分享 |
| 传输详情 | 当前/最近一次进程内任务，进行中可停止，下载完成可打开文件；不暗示持久下载历史。空状态只保留一个通过链接下载入口 |
| 通过链接下载 | 独立表单；开始后进入详情；返回已有表单保留输入 |
| 设置 | 账户、连接方式、下载偏好和关于；连接检测委托同一状态页，诊断和许可在关于组 |

## 已修正的问题

| 优先级 | 旧行为与影响 | 本轮修正 |
| --- | --- | --- |
| P1 | 搜索请求加载时 clearSearch 直接返回，系统返回键也无效 | 返回可清除已提交搜索，取消旧加载并回原范围；仅清除草稿不重新请求 |
| P1 | 根页面系统返回前永久关闭回调；Android 把任务留后台后，重新进入可能失去目录返回逻辑 | 仅在委托系统期间临时关闭，用 finally 恢复；修改任务进行时允许系统返回，不困住用户 |
| P2 | 文件操作套一层对话框，共享同时出现两处；打开泛操作菜单即要求管理权限 | 展平为有名字的动作；展开菜单只读，明确选择写操作后才使用现有权限检查 |
| P2 | 设置、连接、链接表单和任务详情可反复压入栈，返回路径越来越长 | AppScreens 使用 CLEAR_TOP 与 SINGLE_TOP 回到已有页面，清理其上的页面；保留目标页面本身状态 |
| P2 | 回收站内文件夹点击后仍尝试普通文件夹浏览；共享云盘提供不适用文件动作 | 行点击和菜单同时约束；六项边界测试覆盖不同对象 |
| P2 | 主菜单重复连接入口，设置又有独立检测操作 | 浏览页保留可见连接入口，设置使用连接状态与检测，检测控制集中一处 |
| P2 | 菜单打开后列表上下文改变，旧菜单仍可能操作旧条目 | 菜单捕获 requestVersion，变化或正在加载/修改时拒绝选择 |
| P2 | “查看传输与已下载文件”暗示持久下载列表，实际仅保存进程内快照 | 统一称传输详情；空状态移除重复入口 |
| P2 | 设置账户摘要把恢复失败或需要确认也概括为等待恢复 | 复用 ConnectionText.account，恢复中、需要确认、暂时失败和撤销分别显示 |

## 安全与功能约束

所有写操作仍走 managementReady、会话租约和 MutationCoordinator；永久删除、移至回收站及公开共享仍有对应确认。明确点击共享才打开权限/人员选择，填写人员前先检查管理权限，避免确认授权后丢失刚填的邮箱。没有修改 API、下载、TLS、签名或令牌持久化策略。

AppScreens 用于应用辅助页面；预览使用文件/会话参数创建专用页面，系统选择器和外部打开文件仍使用各自原生 Intent，不能混用页面复用规则。

## 验证与设备待验收

六项 FileMenu JVM 回归检查正常文件、禁用下载、文件夹、快捷方式、回收站及共享云盘入口。完整入口为 tools/check.sh：每变体 201 项 JVM 测试、11 项独立检查、实际编译和 Lint。账户摘要复用已有状态文案测试。页面栈和系统 Back 修复已检查源码与真实 Android 编译；没有将其描述为真机手势自动化通过。

手机还需覆盖：加载中返回、根任务后台恢复后进入子目录再返回；两组页面循环跳转和旋转；菜单滚动与大字体；断网/慢网、只读授权和取消；永久删除确认；夜间和 TalkBack。大屏仍保留现有宽度约束与导航适配边界，本轮未扩展成平板双栏或声称全设备布局完成。
