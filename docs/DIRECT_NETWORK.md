# Google 前端发现与数据连接（0.5.0）

目标是让用户无需另外配置应用代理即可访问可达的 Drive 数据服务。实现区分真实 Google 前端与第三方中转，不把“HTTPS 能连通”当作运营方归属证明。当前默认自动模式只接受 Google 公布的非 Cloud IPv4 范围；没有自动借用第三方中转。

## 2026-10-26 勘误与实现选择

维护者提供的原项目作者勘误明确指出 `183.56.143.147` 是第三方反向代理。此前交付的 0.4.0/db055eb 包含它作为候选，不能称为 Google 官方节点。0.5.0 移除该提示，在候选/旧缓存/手工路径拒绝它，并首次清除旧线路和历史提示。原作者 0.7/0.8 的“官方范围扫描”与“中转优先”是两条不同路线；本版独立实现前者的范围约束和移动端探测，不复制源码、补丁、前端种子或 IP 资产。

中转也有技术区别：TCP/TLS 透传可以保留 Google 端到端 TLS；终止 TLS 的 HTTP 反向代理会接触明文。只有地址与证书、协议验证才能判断，不能从“反代”二字推断具体实现。当前没有经过验证的自有或明确授权中转配置，所以没有将某个陌生第三方服务作为自动兜底。泄露的 CA 私钥不能提供网络通道，客户端也不需要靠它建立自己的转发方案。

## 自动发现流程

1. 通过系统网络下载 Google 官方 `https://www.gstatic.com/ipranges/goog.json` 和 `https://www.gstatic.com/ipranges/cloud.json`，不携带账户、文件标识或凭据，不跟随重定向。每份最多 1 MiB/2.5 秒，校验结构与至少 20 条 IPv4 前缀，拒绝明显不完整列表。更新走系统网络，数据直连仍使用 NO_PROXY。
2. 独立计算 goog.json IPv4 集合减去 cloud.json 集合，处理前缀合并、嵌套、分割和边界。它提供候选范围，不代表其中每个 IP 都提供 Drive 服务。缓存原始官方数据采用应用私有 AtomicFile，每七天尝试更新；失败可保留不超过 30 天的最后成功缓存，一小时后再尝试，“重新检测”会清除更新退避。
3. 同时收集 Android 可取消系统 DNS 和 Google Public DNS HTTPS JSON 的结果（最多 1.8 秒），仅查询公开 Google 数据域名。加密 DNS 使用 Google 公布的 8.8.8.8/8.8.4.4 连接 dns.google，标准 TLS/无 SNI 都验证其真实域名，请求不转发用户子网、不带 Authorization/Cookie。
4. DNS、加密 DNS、历史成功地址和已缓存路线全部按当前官方非 Cloud 范围过滤。系统 DNS 被污染到范围外的结果会丢弃。手工公开下载 IP 也受此约束。
5. 在官方范围中独立随机抽取最多 48 个候选进行 TCP 443 预检，最多 12 个工作线程、每次连接 250ms、总计 1.5 秒，保留最多 8 个可达结果。每次重新检测会重新抽样；不是全网扫描，也不是桌面端一次 2048 个连接的复制。
6. 对 DNS/历史/预检候选逐个尝试标准 TLS 和无 SNI，最多 16 个地址、6 个并行 TLS/HTTP 探测。始终保持真实 URL 和 HTTP Host；无 SNI 用数字对端创建 TLS，最终仍验证真实 Google 域名。API 探测还要求预期 401 错误 JSON；TCP 成功本身不会接收账号令牌。
7. 首先通过验证的线路按域名缓存 24 小时，同一路线复用连接；请求失败淘汰/换线，切网清路线与空闲连接并重新验证。单个域名发现预算 12 秒（含 DNS/TCP，不含首次官方列表下载最多 5 秒）；没有可用结果时明确失败，不自动回退陌生中转。手动重测的两个目标域名分别执行上述流程。

当前安装包没有内置完整 Google 地址快照；首次自动模式需要取得上述公开官方列表，此后可使用有效缓存。因此这项实现减少了对被污染数据域名 DNS 的依赖，并不等于任何离线冷启动或任意地区都能成功。不能取得有效列表时保留失败，用户可显式选择系统网络。

## 证书与认证边界

- 平台 CA 信任和真实主机名校验继续启用，不用 trust-all，也不使用泄露私钥伪造 Google 证书。
- 针对 emSign 事件，在网络拦截器中、TLS 成功后发送 HTTP 前，额外拒绝 emSign/eMudhra 名称的证书链与已公布的 emSign ECC Root CA G3 SPKI。这是保守的 CA 家族排除，不是对所有未来 CA 事件的保证，不替代系统安全更新。它不替换 Android TrustManager。
- 根 SPKI 依据 https://github.com/rustls/webpki-roots/pull/133 ，事件依据 https://github.com/qutebrowser/qutebrowser/issues/9032 。未导入这些项目代码。
- 私人请求只允许精确 Drive API origin/路径，不跟随重定向；令牌与资源密钥只在内存，真正发送前检查当前会话。
- Google 官方账号选择、授权、令牌获取及撤销仍走其系统服务网络。本应用附加证书策略适用于自己的数据、DNS 和列表请求，不能替换 Google Play 服务内部的信任配置。
- NO_PROXY 跳过应用层 HTTP 代理，不绕开 Android VPN/TUN。地址属于 Google 不意味着物理路径不出境，也不证明网络内没有 TCP 转发或运营商路由变化。

## 已验证与待验收

JVM 夹具验证 IPv4 集合运算、Cloud 排除、污染/旧中转过滤、随机候选不越界、TCP 阶段取消、官方缓存复用/完整性/过期与更新失败、无凭据/禁止重定向的列表请求；真实回环 TLS 验证默认信任原本可接受的 emSign 测试链被附加策略拒绝，包含复用连接，且 Authorization 未发送。原有 SNI/主机名/CA/重定向/换线及传输测试继续执行。

云环境遵守代理/网络策略，没有直拨公网 IP 或使用 CI 充当代理来伪造中国网络测试。尚未取得本版本真机官方列表、登录、私人传输和国内运营商网络结果；也未宣称全域 Google 服务支持或完整全地址扫描。设备验收应记录实际模式、目标域名/IP、TLS 模式、是否关闭代理/VPN、官方列表能否获取及文件哈希结果。
