# 自动直连的数据通道

目标是在部分无法通过普通域名连接 Google 的网络中，让 Drive 文件浏览和文件传输直接连接可达的服务地址。不是要求用户先配置代理才能使用的普通 Drive 客户端。可达地址随网络而变，本实现不能保证所有地区、运营商和时间都可用。

## 参考的功能流程

按维护者要求，只读核对了 `mizorewww/gdirect` 提交 `f4b67efb3f96ba061e89ac956b0b0335a481b007` 的 README 和扫描、授权、存储相关流程。借鉴的是首次使用自动检测、成功地址缓存 24 小时、数据通道指定 IP、SNI 与证书身份分开、登录与数据通道分离这些行为。没有把其 Rust / aria2 实现、补丁、测试、IP 资产或原生库导入、翻译到 Android 工程。

Android 网络实现使用 Apache-2.0 的 OkHttp 4.12.0。它的自定义 DNS 在建立 TCP 连接前指定目标地址，URL、HTTP Host 和证书校验仍使用真实 Google 域名。替换了原型在 `HttpsURLConnection` 的 SSL factory 中另行拨号的办法；后者不能可靠地避免底层先进行系统 DNS/连接。

## 使用流程

1. 下载页默认选择“自动直连”，无需先点击检测或填写 IP。私人浏览和私人下载也采用同一选择。
2. 首次访问某个数据域名时自动检测；并行最多 6 个无凭据探测，每个域名总预算 12 秒，单个 HTTP 探测最多 3 秒。DNS 候选收集最多 1.2 秒，包含在总预算内。
3. 候选来自本机 DNS、以前通过验证的地址及现有 Java 原型的一个未受信任的引导候选。仅使用公网 IPv4，排除内网、文档、组播及 `198.18.0.0/15` fake-IP 等地址。当前候选覆盖有限，没有内置第三方项目的 IP 列表，也不是全网扫描器。
4. 每个候选尝试标准 TLS 和无 SNI；两者都使用系统 CA 信任链及真实 URL 域名验证。API 探测还须返回符合预期的未授权错误 JSON；其他数据域名的探测只证明 TLS/HTTP 连通性，不证明某个文件可下载。
5. 复用首先完成验证的线路，按域名缓存最多 24 小时、最多 32 个域名。新域名须单独验证。切换默认网络清除可用线路缓存，但保留最多 16 个历史地址作为待重新验证的候选，避免进入 DNS 不可用的网络后丢失全部线索；新请求的证书仍会验证，缓存 IP 不构成信任依据。
6. 建立请求失败时淘汰该线路、短期避开它并最多换线重试一次 GET。传输中断会淘汰线路，但不会在流内重放已读字节；公开分块按既有 Range/ETag 规则重试，私人单流失败后需重新下载。没有可用线路时显示失败和已完成探测数，不自动改走代理；自动失败有短暂冷却，“重新检测直连”可清除冷却。
7. “重新检测直连”依次检查 API 和公开数据两个域名，各有独立预算和结果，可取消。它不是下载必要步骤。“系统网络”是显式可选方式，遵循设备 DNS/代理设置。高级手填 IP 仅覆盖公开下载。

Google 的账号选择、授权、重新获取令牌及远端撤销由官方 Android 服务通过系统网络完成。原桌面项目的登录及刷新同样与指定 IP 的数据通道分开。Google 身份服务无法访问时，数据直连功能不会自动解决登录问题。Android 版本不存储刷新令牌。

## 安全与验证

- 无 SNI 只关闭 TLS 的 Server Name 扩展，不关闭证书链验证，也不把 IP 当作待验证域名。没有 trust-all、伪造证书或自定义的宽松主机名校验。
- 探测不携带账户令牌或私人文件 ID。私人 Authorization 仍只允许精确 Drive API origin 和受控路径，禁止重定向；探测结束、真正发送请求前再次检查会话有效性。
- 本地持久化仅包含数据域名、已验证候选 IP、TLS 模式和验证时间，不包含账户、令牌和文件信息。诊断可以复制连接方式及公开域名/IP，不复制私人请求 URL。
- `Proxy.NO_PROXY` 跳过应用层代理，不会绕开 Android VPN/TUN 的路由。检验免代理能力时应关闭代理及 VPN/TUN，或核实这些连接确实使用直连路由。
- JVM 测试在本地回环地址进行真实 TLS 握手：正确域名成功、错误域名和不可信 CA 均在发送 HTTP Authorization 前被拒绝；实际观测标准/无 SNI 扩展。同时验证换线、流中断、会话失效、重定向、缓存时效、取消及网络切换。
- 云环境出网遵循其代理/网络策略，没有用云端直拨公网 IP 绕过策略来伪装实际网络验证。Android 无 SNI 的平台行为、关闭代理后的私人浏览/下载及中国运营商网络仍需设备验证。编译或本地 TLS 测试通过不等于这些验收已完成。

建议用手机分别记录 Wi-Fi/移动网络、是否关闭代理/VPN、实际选择的域名/IP/TLS 模式、能否列出私人文件、能否下载已知内容并核对哈希。只报告测试结果，不提供账户密码或令牌。更新 APK 前先解决签名连续性，保留当前能登录的应用。
