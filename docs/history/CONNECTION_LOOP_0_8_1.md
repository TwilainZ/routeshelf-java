# 0.8.0 目录循环回归与 0.8.1 修复

维护者于 2026-11-08 提供 0.8.0-ui-preview/code 15、897bf3922d773113556ea78987f1a750cf878295 的连接报告。这里只保留无账户/文件信息的分析结论，不附私人数据或完整设备日志。

## 观察及代码对应

- 多次 LIST_READY 后，下一次 LIST_BEGIN 总在前一次 LIST_DISPLAYED 之前出现，约每 0.5～1.2 秒重复。DriveActivity 在成功处理的 updateControls() 中调用 Material setSelectedItemId()，重复选择当前标签会同步分发重新选中回调；该回调没有检查程序同步标志，于是再次 load(false)。这次更新移除无变化的选择调用，并为选择/重新选择两个回调加相同隔离。
- 目录请求使用 192.179.60.132/GOOGLE_FRONT 得到 HTTP 200。一次正文取消后变成 192.179.61.100/NORMAL。GoogleHttp 的正文 IOException 分支无条件运行 failed 回调，因而主动取消也会拒绝健康路线。现在正文失败先检查取消与账户/策略守卫，取消不会执行路线拒绝；真实断流仍执行。
- 同一日志一次请求等待 56,797ms 后才重试，改用同 IP 的 GOOGLE_FRONT 后成功。原 HTTP 只有连接/单次读取空闲超时，没有整次调用时限。新增元数据 GET 的 12 秒整次尝试上限，5 秒连接与 8 秒读取空闲上限；已有更短时限优先。选线预算、原上层幂等读取重试独立存在，不能把 12 秒描述为整个用户操作必定完成的上限。传输与写操作不套用元数据时限。

RELAY_ALLOWED 是策略许可。该段实际选择的是 Google 地址，没有选择已知第三方中转。报告没有设备 VPN 状态，也没有 DOWNLOAD_BEGIN/文件传输结果；这里不将目录成功视为真实下载完成或无 VPN 网络验收。

## 本地证据

- 修复前新增取消正文回归测试失败：关闭一个已收到响应头的真实 TLS 连接后继续读取，健康路线被错误拒绝。日志 `/tmp/gdirect-loop-cancel-before.log` 为临时构建输出，不作为交付物。
- 修复后同一测试通过，并验证账户/网络失效不拒绝路线、真实正文断流仍拒绝路线。
- 真实回环 TLS 测试覆盖元数据有效时限、既有更短整次时限、响应头及正文阶段超时的分类/换线，以及 media/export/Range/写操作不被套用元数据限制。测试证书只用于本机服务器，不改变生产信任库。
- NavigationSelection 的 JVM 测试模拟同步选择/重新选择回调、多次成功后同步、嵌套和异常恢复，检查界面渲染不发起加载、真实用户事件仍生效。它不是手机 Material 自动化测试。

完整检查入口为 `bash tools/check.sh`：每变体 191 项 JVM 测试、11 项独立检查、实际编译与 Lint。安装身份继续使用 dev.gdirect.lite.preview 及原保留证书；真实设备界面、账号传输和运营商表现保留为手机验收项目。
